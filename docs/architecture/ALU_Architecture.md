# Arithmetic Logic Unit (ALU) Architecture

## 1. Overview

The Arithmetic Logic Unit (ALU) is one of the core computational blocks of the RV32I processor. It performs all arithmetic, logical, shift, and comparison operations required by the RISC-V Integer Base Instruction Set (RV32I).

The ALU receives two 32-bit operands from the datapath and performs the operation selected by the ALU Control Unit. The resulting output is forwarded either to the Register File during the write-back stage or to the Data Memory during address calculations.

The ALU is implemented as a purely combinational circuit, allowing the output to update immediately whenever the input operands or operation code change.

---

# 2. Features

- Parameterized data width (default: 32 bits)
- Pure combinational implementation
- Complete RV32I arithmetic support
- Complete RV32I logical support
- Shift operations
- Signed and unsigned comparison operations
- Zero flag generation
- Modular and reusable RTL design

---

# 3. Module Interface

| Signal | Direction | Width | Description |
|---------|-----------|------:|-------------|
| operand_a | Input | DATA_WIDTH | First ALU operand |
| operand_b | Input | DATA_WIDTH | Second ALU operand |
| alu_op | Input | 4 | Operation select signal |
| result | Output | DATA_WIDTH | Computed ALU result |
| zero | Output | 1 | Asserted when result equals zero |

# 5. Internal Architecture

```
                +----------------------+
 operand_a ---->|                      |
                |                      |
 operand_b ---->|        ALU           |-----> result
                |                      |
    alu_op ---->|                      |
                +----------------------+
                           |
                           |
                           +-----------> zero
```

The ALU consists of a combinational case statement that selects the required operation based on the ALU operation code. Since no sequential elements are used, the module does not require a clock or reset signal.

---

# 6. Design Decisions

## Parameterization

The ALU data width is parameterized using the `DATA_WIDTH` parameter. Although the current processor targets RV32I (32-bit), parameterization allows future extension to wider datapaths.

## Combinational Implementation

The ALU is implemented using an `always @(*)` block to ensure purely combinational behavior.

## Default Assignment

The output is initialized at the beginning of the combinational block to prevent unintended latch inference and to guarantee deterministic behavior.

## Shift Operations

The lower five bits of `operand_b` are used as the shift amount, complying with the RV32I specification, which defines valid shift amounts from 0 to 31.

## Signed Operations

The `SRA` and `SLT` operations use `$signed()` to correctly interpret operands as signed two's complement values.

## Zero Flag

A dedicated zero flag is generated by comparing the ALU result against zero. This flag is used by branch instructions such as BEQ and BNE.
