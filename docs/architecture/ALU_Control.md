# ALU Control Unit Architecture

## 1. Overview

The ALU Control Unit is a combinational logic block that determines the exact operation to be performed by the Arithmetic Logic Unit (ALU).

The Main Control Unit determines the general class of operation using `ALUOp`. The ALU Control Unit then uses `ALUOp`, `funct3`, and `funct7` to generate the 4-bit ALU operation code used by the ALU.

This provides a two-level instruction decoding structure.

---

## 2. Module Location

```text
rtl/core/alu_control.v
```

---

## 3. Features

- Pure combinational implementation
- Supports RV32I R-Type ALU operations
- Supports RV32I I-Type ALU operations
- Supports address calculations
- Supports branch comparison through subtraction
- Uses shared ALU operation definitions
- Fully synthesizable RTL
- Safe default operation

---

## 4. Module Interface

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `ALUOp` | Input | 2 bits | Operation class from Main Control Unit |
| `funct3` | Input | 3 bits | Instruction `funct3` field |
| `funct7` | Input | 7 bits | Instruction `funct7` field |
| `alu_control` | Output | 4 bits | Exact operation code sent to the ALU |

---

## 5. Two-Level ALU Decoding

The ALU operation is determined in two stages.

```text
                 Instruction
                      |
                      v
                   opcode
                      |
                      v
             Main Control Unit
                      |
                    ALUOp
                      |
                      v
              ALU Control Unit
                 ^           ^
                 |           |
              funct3       funct7
                      |
                      v
                ALU Operation
```

The Main Control Unit determines the broad operation category, while the ALU Control Unit determines the exact operation.

---

## 6. ALUOp Encoding

| `ALUOp` | Meaning | ALU Operation |
|---|---|---|
| `2'b00` | Address calculation | ADD |
| `2'b01` | Branch comparison | SUB |
| `2'b10` | R-Type / I-Type ALU operation | Decode `funct3` and `funct7` |

### ALUOp = `00`

Used for address calculations such as:

- LB
- LH
- LW
- LBU
- LHU
- SB
- SH
- SW
- JALR

The ALU performs:

```text
Base Register + Immediate
```

Therefore:

```text
ALUOp = 00 -> ALU_ADD
```

### ALUOp = `01`

Used for branch comparison.

The current implementation uses subtraction:

```text
Register A - Register B
```

For equality comparison, a zero result indicates that the operands are equal.

Therefore:

```text
ALUOp = 01 -> ALU_SUB
```

### ALUOp = `10`

Used for R-Type and I-Type ALU instructions.

The exact operation is determined using `funct3` and, where required, `funct7`.

---

## 7. R-Type ALU Operations

All R-Type ALU instructions use:

```text
Opcode = 0110011
```

The exact operation is determined using `funct3` and `funct7`.

| Instruction | `funct7` | `funct3` | ALU Operation |
|---|---|---|---|
| ADD | `0000000` | `000` | `ALU_ADD` |
| SUB | `0100000` | `000` | `ALU_SUB` |
| SLL | `0000000` | `001` | `ALU_SLL` |
| SLT | `0000000` | `010` | `ALU_SLT` |
| SLTU | `0000000` | `011` | `ALU_SLTU` |
| XOR | `0000000` | `100` | `ALU_XOR` |
| SRL | `0000000` | `101` | `ALU_SRL` |
| SRA | `0100000` | `101` | `ALU_SRA` |
| OR | `0000000` | `110` | `ALU_OR` |
| AND | `0000000` | `111` | `ALU_AND` |

---

## 8. I-Type ALU Operations

I-Type ALU instructions use:

```text
Opcode = 0010011
```

The ALU Control Unit maps them to the corresponding ALU operation.

| Instruction | `funct3` | Additional Encoding | ALU Operation |
|---|---|---|---|
| ADDI | `000` | — | `ALU_ADD` |
| SLTI | `010` | — | `ALU_SLT` |
| SLTIU | `011` | — | `ALU_SLTU` |
| XORI | `100` | — | `ALU_XOR` |
| ORI | `110` | — | `ALU_OR` |
| ANDI | `111` | — | `ALU_AND` |
| SLLI | `001` | `funct7 = 0000000` | `ALU_SLL` |
| SRLI | `101` | `funct7 = 0000000` | `ALU_SRL` |
| SRAI | `101` | `funct7 = 0100000` | `ALU_SRA` |

The ALU does not need separate operations for ADD and ADDI, or for SRL and SRLI. The `ALUSrc` signal generated by the Main Control Unit determines whether the second ALU operand comes from a register or the immediate.

---

## 9. Existing ALU Operation Definitions

The ALU Control Unit uses the operation definitions already established in `rv32i_defs.vh`.

```verilog
`define ALU_ADD    4'b0000
`define ALU_SUB    4'b0001
`define ALU_AND    4'b0010
`define ALU_OR     4'b0011
`define ALU_XOR    4'b0100
`define ALU_SLL    4'b0101
`define ALU_SRL    4'b0110
`define ALU_SRA    4'b0111
`define ALU_SLT    4'b1000
`define ALU_SLTU   4'b1001
`define ALU_PASS_B 4'b1010
```

These definitions are shared between the ALU Control Unit and the ALU.

No duplicate ALU operation encoding is used.

---

## 10. Important Decode Cases

### ADD vs SUB

Both instructions have:

```text
funct3 = 000
```

The distinction is made using `funct7`.

```text
ADD:
funct7 = 0000000
funct3 = 000

SUB:
funct7 = 0100000
funct3 = 000
```

Therefore:

```text
0000000 + 000 -> ALU_ADD
0100000 + 000 -> ALU_SUB
```

### SRL vs SRA

Both instructions have:

```text
funct3 = 101
```

The distinction is again made using `funct7`.

```text
SRL:
funct7 = 0000000
funct3 = 101

SRA:
funct7 = 0100000
funct3 = 101
```

Therefore:

```text
0000000 + 101 -> ALU_SRL
0100000 + 101 -> ALU_SRA
```

These cases demonstrate why both `funct3` and `funct7` are required for complete ALU decoding.

## 12. Design Decisions

### Shared ALU Definitions

The ALU Control Unit does not define a new operation encoding. It uses the existing `ALU_*` definitions from `rv32i_defs.vh`.

This keeps the ALU and ALU Control Unit synchronized.

### Combinational Logic

The module contains no clock or state.

The output changes immediately when any of the inputs change.

### Safe Default

The default ALU operation is:

```text
ALU_ADD
```

This prevents an unknown or unsupported control combination from producing an undefined ALU control value.

---

## 13. Relationship With the ALU

The ALU Control Unit translates the RISC-V instruction encoding into the internal ALU operation encoding.

```text
RISC-V Encoding
      |
      | funct3/funct7
      v
ALU Control Unit
      |
      | 4-bit ALU operation
      v
      ALU
```

For example:

```text
ADD instruction
      |
      v
funct3 = 000
funct7 = 0000000
      |
      v
ALU Control
      |
      v
ALU_ADD
      |
      v
ALU performs addition
```
