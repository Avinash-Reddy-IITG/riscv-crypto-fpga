# Write-Back Unit Architecture

## 1. Overview

The Write-Back Unit selects the value that is written into the destination register (`rd`) at the end of an instruction.

Different RV32I instructions obtain their result from different parts of the datapath.

The Write-Back Unit provides a single output:

```text
rd_data
```

which is connected to the write-data input of the Register File.

The unit is implemented as a purely combinational multiplexer.

---

## 2. Module Location

```text
rtl/core/write_back.v
```

---

## 3. Write-Back Sources

The module supports three valid write-back sources.

| `wb_src` | Source | Typical Instructions |
|---|---|---|
| `00` | ALU result | R-type and ALU-immediate instructions |
| `01` | Data Memory | Load instructions |
| `10` | PC + 4 | JAL and JALR |
| `11` | Reserved | Produces zero |

---

## 4. Module Interface

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `alu_result` | Input | 32 | Result generated by the ALU |
| `memory_data` | Input | 32 | Data returned by Data Memory |
| `pc_plus_4` | Input | 32 | Address of the instruction following the current instruction |
| `wb_src` | Input | 2 | Selects the write-back source |
| `rd_data` | Output | 32 | Data written into the destination register |

---

## 5. ALU Result Write-Back

For arithmetic and logical instructions, the ALU produces the result.

Example:

```assembly
add x5, x6, x7
```

The Register File supplies the operands:

```text
x6 -> ALU input A
x7 -> ALU input B
```

The ALU produces:

```text
alu_result = x6 + x7
```

The control unit selects:

```text
wb_src = 00
```

Therefore:

```text
rd_data = alu_result
```

and the Register File eventually performs:

```text
x5 <- rd_data
```

---

## 6. Data Memory Write-Back

Load instructions obtain their result from Data Memory.

For example:

```assembly
lw x5, 8(x1)
```

The ALU calculates the effective address:

```text
address = x1 + 8
```

Data Memory then provides:

```text
memory_data
```

The control unit selects:

```text
wb_src = 01
```

Therefore:

```text
rd_data = memory_data
```

The value is subsequently written to `rd`.

This path also supports:

```text
LB
LBU
LH
LHU
LW
```

because Data Memory is responsible for producing the appropriately extended 32-bit result.

---

## 7. PC + 4 Write-Back

JAL and JALR instructions need to save the return address in `rd`.

The return address is:

```text
PC + 4
```

For example:

```assembly
jal x5, label
```

The processor performs two operations:

```text
1. next_pc = JAL target
2. x5 = PC + 4
```

The Write-Back Unit handles the second operation.

The control unit selects:

```text
wb_src = 10
```

resulting in:

```text
rd_data = pc_plus_4
```

This allows the Next-PC and Write-Back paths to operate independently.

---

## 8. JALR Write-Back

JALR also writes the return address into `rd`.

For:

```assembly
jalr x5, 8(x1)
```

the processor:

```text
1. Calculates the JALR target.
2. Updates the PC to the target.
3. Writes PC + 4 into x5.
```

The Write-Back Unit therefore uses:

```text
wb_src = 10
```

for JALR as well.

---

## 9. Reserved Control Value

The value:

```text
wb_src = 11
```

is currently reserved.

The implementation produces:

```text
rd_data = 0
```

for this selection.

This provides deterministic behavior and avoids an undefined output if an invalid control combination reaches the module.

---

## 10. Architecture

The Write-Back Unit sits between the ALU/Data Memory/PC paths and the Register File.

```text
                    +-------------+
                    |     ALU     |
                    +------+------+
                           |
                      alu_result
                           |
                           v
                     +-----------+
                     |           |
memory_data -------->| Write-Back|------> rd_data
                     |    MUX    |
pc_plus_4 ---------->|           |
                     +-----------+
                           |
                           v
                    +-------------+
                    | Register    |
                    |    File     |
                    +-------------+
                           |
                           v
                           rd
```

The `wb_src` signal controls which input is selected.

---

## 11. Separation of Responsibilities

The Write-Back Unit does not determine which instruction is being executed.

Instead, the Main Control Unit eventually generates the appropriate:

```text
wb_src
```

The Write-Back Unit only performs the selection.

This keeps instruction decoding separate from datapath multiplexing.

---

## 12. Combinational Operation

The Write-Back Unit does not contain any state.

There is no clock or reset because the module only selects between existing datapath values.

The actual register update occurs inside the Register File on the active clock edge.

The data flow is:

```text
ALU / Memory / PC + 4
          |
          v
    Write-Back MUX
          |
          v
       rd_data
          |
          v
     Register File
          |
       posedge clk
          |
          v
          rd
```

---

## 13. Parameterization

The module contains:

```verilog
parameter DATA_WIDTH = 32
```

The default value is 32 because this processor implements RV32I.

The parameter allows the datapath width to be changed if required.

---

## 14. Design Decisions

### Single Write-Back Output

All possible result sources are converted into one signal:

```text
rd_data
```

This simplifies the interface to the Register File.

### Separate PC + 4 Path

`PC + 4` is kept as a dedicated input because JAL/JALR need it for the return address even though the Next-PC Unit may simultaneously select a different PC target.

### Safe Reserved State

The unused `wb_src = 11` selection produces zero.

This ensures deterministic simulation behavior.
